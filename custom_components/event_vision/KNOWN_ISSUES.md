# Known Issues & Concrete Operational Limitations (Event Vision)

This document describes operational limitations and architectural boundaries of the `event_vision` integration.

---

## 1. Multi-Camera Visual Fusion Opt-In & API Costs
- **Experimental and Disabled by Default**: Visual fusion is opt-in (`enable_fusion = False`) and can issue additional Google Gemini requests with associated token usage and cost. Cross-view results are uncertain hypotheses, and fusion is not live-tested on this Home Assistant installation.
- **Minimum Requirements**: Fusion requires at least two distinct camera views with finalized member analyses. If fewer views exist, the job is cleanly marked skipped (`INSUFFICIENT_VIEWS`).

## 2. In-Flight Incident Deferral
- **Bounded Deferral (5 Seconds)**: When an incident notification arrives while member events are still recording or undergoing individual analysis (`pending` or `processing`), fusion execution defers with a fixed 5-second backoff (`defer_seconds = 5.0`). This avoids tight SQLite/CPU polling while giving member analyses time to finalize.

## 3. Media Pin Cleanup & DB Failure Fallback
- **Active Pin Lifecycle**: Media lease pins are explicitly released in worker `finally:` blocks upon job completion, provider failure, or task cancellation.
- **TTL Expiration Fallback**: If database release fails or the process terminates, pins can remain until their lease expires. Expired pins stop blocking the configured retention policy.

## 4. Model Uncertainty & Identity Correspondence
- **Probabilistic Hypotheses**: Cross-view correspondences generated by Gemini are probabilistic hypotheses referencing specific frame tokens (e.g. `view1_frame0`).
- **No Identity Proof**: Visual similarity or temporal co-occurrence does NOT constitute proof of personal identity.

## 5. Cloud Latency & Non-Blocking Isolation
- **Network / Rate Limiting**: External API latency, rate limits (HTTP 429), or temporary outages cause leased analysis jobs to back off and retry.
- **Intake Isolation**: Cloud responses do not block event intake or capture. Analysis pins intentionally defer retention while active.

## 6. Visual UTC Provenance
- **Source-Dependent Timing**: Extracted frame timestamps inherit the source media's qualified timing quality. When camera clocks are uncalibrated or PTS is relative, visual frame UTC remains marked `"estimated"` or `"unknown"`.

## 7. Deferred Structural Architectural Follow-Ups
The following architectural refactorings are documented follow-up roadmap items deferred from PR #9 to avoid high-risk pre-release rewrites:
- **Generic Queue Unification**: Migrating `AnalysisJobStore` and `FusionJobStore` into a single unified `event_vision_jobs.db` database and schema.
- **Keyframe Cache Reuse**: Reusing per-event extracted keyframes during multi-camera visual fusion to reduce duplicate FFmpeg frame extraction.
- **Module Decomposition**: Separating `VisionCoordinator` integration glue and `AnalysisWorker` execution pipelines into distinct modules.
