# Known Issues & Concrete Operational Limitations (Event Vision)

This document describes operational limitations and architectural boundaries of the `event_vision` integration (version 0.4.0).

---

## 1. What Shipped in Version 0.4.0
- **Unified Queue Engine:** Introduced `QueueEngine` (`core/queue.py`) implementing declarative `QueueSpec` policies, per-claim `lease_token` fencing, and strict claim validation across both `VisionStore` (`analysis_jobs`) and `FusionStore` (`fusion_jobs`).
- **Separate SQLite Databases Maintained:** Kept separate SQLite database files on disk (`event_vision_analysis.db` and `event_vision_fusion.db`) to avoid risky schema migration while sharing the unified queue engine core.
- **Bounded In-Memory Frame Cache:** Implemented `FrameCache` (`core/cache.py`) providing strictly in-memory (RAM-only, zero disk spillover) caching of decoded frames with explicit `frame_cache_mb` (0-512 MB) and `frame_cache_ttl` (10-86400s) options, canonical source fingerprinting (canonical path, size, mtime, dev/inode), waiter-safe singleflight deduplication, and full-event multi-chunk sampling preservation.
- **Coordinator & Worker Architecture:** Modularized queue coordination and execution lifecycle helpers into `core/coordinator.py`.
- **Shared Declarative Validation:** Reused declarative validation foundation from `custom_components.event_recording.core.validation` (`NumberSpec`, `StringSpec`, `IdSpec`, and `SpecNumberSelector`), strictly rejecting booleans, non-finite values, fractions, huge integers, and control characters before form coercion.

---

## 2. Minimum Dependency & HACS Upgrade Order
- **Dependency Requirement**: `event_vision 0.4.0` requires `event_recording >= 0.5.0` for the shared declarative validation modules.
- **HACS Operator Upgrade Instruction**: When updating via HACS, operators must update both **Event Recording** and **Event Vision** before restarting Home Assistant.

---

## 3. Multi-Camera Visual Fusion Opt-In & API Costs
- **Experimental and Disabled by Default**: Visual fusion is opt-in (`enable_fusion = False`) and can issue additional Google Gemini requests with associated token usage and cost. Cross-view results are uncertain hypotheses, and fusion is not live-tested on this Home Assistant installation.
- **Minimum Requirements**: Fusion requires at least two distinct camera views with finalized member analyses. If fewer views exist, the job is cleanly marked skipped (`INSUFFICIENT_VIEWS`).

---

## 4. In-Flight Incident Deferral
- **Bounded Deferral (5 Seconds)**: When an incident notification arrives while member events are still recording or undergoing individual analysis (`pending` or `processing`), fusion execution defers with a fixed 5-second backoff (`defer_seconds = 5.0`). This avoids tight SQLite/CPU polling while giving member analyses time to finalize.

---

## 5. Media Pin Cleanup & DB Failure Fallback
- **Active Pin Lifecycle**: Media lease pins are explicitly released in worker `finally:` blocks upon job completion, provider failure, or task cancellation.
- **TTL Expiration Fallback**: If database release fails or the process terminates, pins can remain until their lease expires. Expired pins stop blocking the configured retention policy.

---

## 6. Model Uncertainty & Identity Correspondence
- **Probabilistic Hypotheses**: Cross-view correspondences generated by Gemini are probabilistic hypotheses referencing specific frame tokens (e.g. `view1_frame0`).
- **No Identity Proof**: Visual similarity or temporal co-occurrence does NOT constitute proof of personal identity.

---

## 7. Cloud Latency & Non-Blocking Isolation
- **Network / Rate Limiting**: External API latency, rate limits (HTTP 429), or temporary outages cause leased analysis jobs to back off and retry.
- **Intake Isolation**: Cloud responses do not block event intake or capture. Analysis pins intentionally defer retention while active.

---

## 8. Visual UTC Provenance
- **Source-Dependent Timing**: Extracted frame timestamps inherit the source media's qualified timing quality. When camera clocks are uncalibrated or PTS is relative, visual frame UTC remains marked `"estimated"` or `"unknown"`. Never upgraded to `"known_utc"` without authoritative clock provenance.

---

## 9. Explicitly Deferred Features (Not Bugs)
- **Single Combined SQLite Database File**: Kept separate SQLite database files on disk (`event_vision_analysis.db` and `event_vision_fusion.db`) using the shared `QueueEngine` to avoid storage migration risks.
- **Live Multi-Camera Fusion Deployment**: Fusion remains opt-in / off by default in live production environments.
- **Storage Schema Migration Wizard**: Automated in-flight database schema migration wizards are deferred.
